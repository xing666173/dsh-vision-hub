# FAQ

## 视觉模型调用报 400「图片输入格式/解析错误」怎么办?

- 先确认图片是常见格式(png/jpeg/webp/gif),且**不是极小图片**(如 1x1):
  部分端点(如 GLM-4V-Flash)会拒绝过小或异常的图片;
- 确认 `maxTokens` 不超过端点上限(glm-4v-flash 为 1024);
- 仍失败请带上完整报错提 issue。

## 返回 429「访问量过大」?

免费端点在高峰时段限流是常态。插件已内置**自动退避重试**(最多 3 次),
仍失败说明端点持续繁忙——稍后再试,或换端点(见 docs/presets.md)。

## 返回 VISION_CONTENT_FILTERED?

图片被视觉端点的内容安全策略拒绝(检测到敏感/不安全内容)。这不是网络或
配置问题——**换一张图片或调整图片内容**即可,不要反复重试。

## 桥接提示是什么?为什么对话里只有 `[图片: 路径]`?

纯文本模型不能接收图片,粘贴的图片会被导出并在对话中替换为
`[图片: <路径>]` 短标记;「看到标记就调用 inspect_image 查看」的规则写在
系统提示段(工具注册时自动注入)。模型仍然看图,对话记录保持干净。

## 工具产物(裁剪/抠图/截图等)存在哪里?

`<工作区>/.dsh-tool-vision/` 目录。长截图 OCR 的产物(分块/ocr.md/manifest)
在同一目录的子文件夹。

## vision_trace / vision_html_screenshot 报依赖缺失?

需要 `potrace` / `puppeteer-core` 可被插件解析。缺失时这两个工具会给出
安装提示,其他工具不受影响。

## 换了视觉模型,为什么缓存没串?

缓存 key 包含 baseURL + model + 图片 + 问题——切换模型不会命中旧答案。

## 与 dsh-tool-vision 上游的关系?

本仓库的 tool-vision/ 是基于上游 0.3.10 的增强版(14 工具 + 修复 + 桥接
改进),独立演进;桥接/预览行为与上游 v0.5.0 的 `bridgePreview` 特性不冲突。
